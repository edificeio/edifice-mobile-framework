# État de la migration

> Mis à jour le **2026-11-19** (branche `feat/ia/migration-outillage`, après la revue de `support`, le découpage en deux skills et l'ordre de migration proposé). À mettre à jour en fin de chaque session (voir [README.md](README.md)).

## Ce qu'il faut savoir avant tout

- **L'app ne charge plus les modules anciens.** `src/app/config/modules.ts` ne liste que les modules nouveaux (et les modules de test `src/app/test/*`), et l'ancien registre `AllModules()` (`src/app/modules.ts`) renvoie `[]`. Un module ancien n'est donc pas « en attente » : il est **absent de l'app** tant qu'il n'est pas migré.
- Le code ancien qui appelle `AllModules().filterAvailables(…)` plante s'il est exécuté : il n'est plus atteignable que par des imports résiduels.
- Les modules **techniques** sont recodés dans `src/modules/`. Les modules **fonctionnels** sont basculés **sur place** dans `src/framework/modules/`, jamais déplacés, sauf s'ils ont déjà un dossier dans `src/modules/` (CONVENTIONS « Portage », 2026-11-19).
- **Deux étapes, deux skills** (2026-11-19, [INTENT.md](../INTENT.md) §4) : la bascule (`/migrate-module`, patron [BASCULE.md](../BASCULE.md)), puis l'assainissement (`/sanitize-module`, un sujet par PR). Plus de passage de Redux à zustand. Le suivi est dans ce dossier, déplacé depuis `docs/migrations/`.

## Questions ouvertes

Points flous à valider ou à débattre. Une question tranchée part dans la fiche concernée (section « Décisions ») et sort de cette liste.

### Architecture

Aucune question ouverte.

Tranchées le 2026-11-19 :

1. **Ouverture des notifications** : une clé de config de module `notifications` (`'<TYPE>.<EVENT>': handler`), lue par le module `notifications` depuis les modules chargés ; même schéma que `entries` et `fileManager` (fiche [timeline.md](timeline.md) §7). Les notifications restent hors de `timeline` (décidé le 2026-11-07).
2. **Reste d'`audience`** : migré **avant** tous ses consommateurs (`blog`, `communities`, `news`, `wiki`), en vague 2.
3. **Gestionnaires de notifications pendant la bascule** : débranchés (geste 19 de [BASCULE.md](../BASCULE.md)), rebranchés avant la livraison. Le suivi calculé ne les compte plus comme navigation ancienne.
4. **Widgets d'accueil** : hors de la migration, faits à part par l'équipe (développements parallèles en cours ; geste 20).

Tranchées le 2026-11-04 : `isModuleAvailable` en phase 0 de `myapps` ; ordre des onglets sur la nouvelle échelle (`timeline` = 0, `myapps` = 40) ; route d'entrée = clé `entry` facultative, dont `tab.route` hérite (**remplacé le 2026-11-17** par `entries`, voir [user.md](user.md) §5.3) ; `useOpenModule` = API publique du framework.

### `myapps`

Aucune question bloquante. Phases 0 à 7 faites (ancien module supprimé), harmonisé le 2026-11-19 ([myapps.md](myapps.md) §9). Reste à tester les phases 4 à 6 dans l'app (et le garde « scroll to top » sur iOS 27), avec la recette de l'harmonisation.
